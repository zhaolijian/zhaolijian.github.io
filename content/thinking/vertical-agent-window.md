做 GEO 的那几个月，我被问得最多的一句话是「大厂做了怎么办」。问的人不是挑衅，是真的在判断要不要进场。

我的回答一直是：这句话问错了对象。真正决定窗口的，不是大厂做不做，而是这个能力会不会被「一次模型升级」顺带做掉。

## 生态已经走到哪一步

我对 LLM 生态有一个粗线条的演化判断，来自各家厂商与基金会近两年的公开公告（截至 2026 年，公开资料口径，结论级转述，具体时间点与范围待核对）：

第一阶段，大厂把 AI 入口和自家生态打通。问答不再只给链接，开始能直接连视频、商城、支付、本地服务。第二阶段，协议层开始统一，工具调用和 Agent 之间的协作有了共同语言，MCP、A2A 这类协议在 2025 年底到 2026 年被主流厂商采纳。第三阶段，少数超级入口并存，B 端按行业纵深碎成垂类。第四阶段，新终端接管一部分场景。

这几个阶段不是串行接力，而是同时发生、互相加速。对做产品的人来说，最关键的含义只有一句：**通用入口的窗口，对个人和小团队已经基本关闭**。那是资源、生态、渠道和商业闭环的竞争，不是产品体验的竞争。

但另一面同样成立：入口越强，被它调用的垂类机会越多。通用入口不可能在所有行业自研，它需要一个「能干活的人」层。

这个结构变化对做产品的人有一个直接含义：产品形态从「做一个完整的助手」变成「做一个能被调用的能力 + 一层只有你有的交付」。前者拼资源，后者拼深度。

这些阶段划分不精确，也不需要精确。产品判断用不上「第几阶段」，用得上的是两个问题：入口是不是越来越集中？集中之后，谁还需要为结果负责？

## 垂直机会在哪：私有数据、交付责任、工作流

我把垂类机会的判断条件收成三条。

**有私有数据。** 客户的合同、工单、实验记录、行业经验，不在公开语料里，模型自己长不出来。这类数据的价值不在「多」，而在「只有在这个场景里才拿得到」。判断「拿不拿得到」可以问三个问题：数据在客户手里还是在平台手里？客户愿不愿意交出来？交出来之后有没有合规限制？三个问题里有一个答案是「不」，这条就不算私有数据。

**有交付责任。** 结果错了要有人负责。法务、医疗、财务、工程变更都属于这一类：需要资质、审计、兜底和可追溯。通用入口不愿意也不能承担这个责任，这就是垂类的位置。

**有工作流。** 不是「问一句答一句」，而是嵌进客户已有的系统与流程：批量任务、审批节点、系统对接、定时执行。工作流越深，越不像一个可以随时切换的聊天窗口。

三条同时满足的方向最稳。只满足「模型能做」的方向最危险——那不是一个产品，是一次调用。

## 窗口的真实形态：被集成，也被替换

协议开放是双刃剑。

好的一面是，垂类 Agent 能被超级入口调用，拿到原本拿不到的分发；用户在你的产品里完成的事，可能是从对话框里点进来的。

坏的一面是，既然能调你，也就能换你。用户记住的是入口，不一定是你。你的能力被封装成一个标准接口之后，差异只剩交付质量。

所以我后来把垂类 Agent 的壁垒总结成三件事：交付质量、数据积累、客户成功。接口可以一夜之间被抄，交付能力不行——它由案例、流程、人、以及出错时怎么兜底组成。

窗口也不是「几年后关闭」，而是「在通用模型补上这个能力之前」。判断方法很朴素：这件事对通用模型来说，是不是一次训练或一次功能更新就能做？如果是，窗口就很短；如果不是（因为数据在客户手里、责任要有人担、流程要一个个接），窗口才值得投入。

还有一个更直接的判断：客户愿不愿意把流程改到你这里来。只愿意「试一下」的需求，撑不起一个产品。另一个信号是客户开始问「能不能给我看一下别人用的效果」——愿意看案例，说明他把这件事当成采购，而不是试用。

如果是小团队，「被集成」更适合当分发策略，而不是依附策略：先把能力做成标准接口，进别人的工作流；同时把交付做实，做到客户遇到问题先找你、而不是先找入口。前者决定有没有量，后者决定能不能留下。

## 不成立的条件

- **通用模型一次升级吃掉功能。** 翻译、润色、通用客服、简单代码生成，这些已经被吃掉，或者正在被吃掉。别在这个范围里找垂类机会。
- **垂类不等于安全。** 行业里可能已经有软件商和大厂，他们握着数据和渠道，你只是更便宜的入口。
- **依赖单一平台分发。** 长在某个超级 App 或某个平台生态里，规则一变就没了。
- **把「现在没人做」当窗口。** 没人做可能是需求不成立，也可能是有人试过、死了。
- **把垂类当成避风港。** 垂类不是小市场，它可能只是「大厂暂时没做」。判断依据仍然是私有数据、交付责任、工作流三条，不是行业热不热。
- **判断有时效。** 我写这些时的生态判断来自公开资料，半年后可能就被推翻。窗口期这个词本身就有投机色彩，它能帮你选时机，但不能替你选方向。

垂类 Agent 真正的机会，不在「大厂还没做」，而在「大厂做了也不想负责」的地方。
