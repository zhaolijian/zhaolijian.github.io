做过的产品与实验：从旗舰项目，到小成本验证

每个案例都尽量写清三件事：产品是做什么的、核心功能怎么设计、边界在哪。案例里的数字均注明是「目标 / 上限」还是「实测」。第 5 个是进行中的实验项目，不是产品。

01

源引 GEO：让品牌出现在 AI 答案里

面向中小企业的生成式引擎优化产品。先诊断品牌为什么没被 AI 提到，再用受控的 Agent 流水线生产「可被摘录」的内容，最后用真人探针在多个 AI 平台上回测可见性。

  • 品牌诊断：把「AI 为什么没提你」拆成信源、信任、采纳三层
  • 内容 Agent：选题预检 → 生成 → 编辑 → 同步到草稿箱
  • 真人探针回测：多平台提问、记录原始回答、按问题集看变化
旗舰产品产品 & 全栈AI AgentGEO
02

阅记：把纸质书笔记变成可复习的知识结构

独立完成调研、PRD、原型、前后端实现与上线：拍照或框选书里的划线句，OCR 后按章节定位并结构化整理，生成思维导图，可导出到常用笔记工具。

  • 拍照 / 框选识别：把书页划线与章节位置对应起来
  • 结构化整理：按金字塔结构归纳要点，而不是只存原文
  • 思维导图与导出：生成导图，支持导出到已有笔记体系
独立 0→1多模态uni-app + Go已内测
03

B 端产品与中台：让复杂能力变成业务方能用的产品

权限与薪酬字段方案、动态配置 / 流控 / 消息队列三类中台组件的 Web 化改造——不只交付 SDK，还交付管理平台、接入文档与自助排查能力。

  • 字段级权限与多端一致：部门负责人 / HRBP 的权限差异落到字段级，覆盖 Web、多维表格与 OpenAPI
  • 薪酬自定义字段：文本 / 数字 / 日期 / 公式等标准字段类型，配置而非定制开发
  • 中台管理台：历史回溯、可视化配置、资源关系与自助排查
B 端产品技术 + 产品平台化
04

AI 产品 0→1 实验：三款 MVP 的快速验证

AI 肤质检测、AI 多人对话播客等 3 款 C 端产品的 MVP：先定义验证问题与信号，再做最小实现，最后判断该不该继续。

  • 独立实现：需求、原型、开发、上线验证全部一个人完成
  • 验证设计：每个产品先写清「要验证什么假设、看哪些信号」
  • 止损判断：把「该不该继续」当成产品动作提前写进计划
OPC 独立开发快速验证止损判断
05

机器鸭：零基础复刻一台 25cm 双足机器人

没有机器人背景，也没有先买硬件：先把官方策略放进 MuJoCo，用 600+ 次压力测试确认软件闭环，再决定是否进入真机阶段。

  • 仿真优先：阶段 0 零硬件成本，先验证策略与异常恢复
  • 测试体系：按键语义、模糊压力、粗糙地面、随机序列五套回归
  • 阶段门：仿真通过后再投入约 4 千元硬件，真机尚未开始
实验项目具身智能MuJoCo进行中
