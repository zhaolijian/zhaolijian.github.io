阅记：把纸质书笔记变成可复习的知识结构

一个纸质书笔记整理助手：拍照或框选书里的划线句，OCR 识别后按章节定位并做结构化整理，自动生成思维导图，再导出到常用笔记软件。它完成上线与小范围内测，最后被主动停掉；留下的是对「用户为什么不用」的判断依据。

我的角色
独立完成：竞品调研、PRD、原型、前后端实现、测试与上线
形态
微信小程序（uni-app 跨端）+ Go 后端
关键能力
OCR、章节定位、金字塔结构化、思维导图生成、导出
状态
上线内测后主动停止（价值假设失效）

问题：纸质书的笔记，记得下但用不起来

读纸质书的人常有两种笔记：划线（捕捉重点）和摘抄（二次加工）。但这两步之后往往没有第三步——笔记散落在纸上或相册里，没有结构、不能检索、复习时也找不到上下文。对学习者来说，真正缺的不是「记录工具」，而是把划线句变成可复习的知识结构的那一步。

我把问题拆成三个具体断点：

  • 录入成本高：手抄划线句太慢，拍照后逐条整理更麻烦；
  • 结构缺失：划线句是碎片，不知道属于哪一章、在书里的什么位置，复习时失去线索；
  • 无法迁移：整理好的笔记留在某个 App 里，无法进入用户已有的笔记体系。

竞品调研：先确认「用户现在怎么解决」

在写 PRD 之前，我先做了一轮横向调研：把市面上 40+ 款笔记、书摘、阅读类产品下载下来，按用户定位、与阅记的功能重复点、可借鉴点、商业化模式、留存设计与技术壁垒做成对比表，并逐个试用。

调研得到的三个关键结论：

  • 专做纸质书摘的产品存在，但只解决「收集」：OCR 框选识别后就结束，不负责按章节整理，更不生成思维导图；
  • 通用笔记软件能覆盖大部分能力，但缺「纸质书」这一步：它们擅长编辑与同步，不擅长从书页照片里恢复结构化上下文；
  • 用户的迁移成本被低估：用户已经有印象笔记 / 飞书 / Notion，产品必须能导出过去，否则只是又一个孤岛。

MVP 的取舍：只做四个核心功能

原始需求列表有 30 多条，我把它收敛到 4 个核心功能，其余全部列为「后续」：

01书籍与笔记管理按书分类；支持手动输入、ISBN、扫条形码导入书籍
02拍照识别与整理识别划线句与框选句，按章节顺序定位并结构化
03阅读与编辑阅读 / 编辑双模式，支持一键格式化与导出
04思维导图基于整理后的笔记生成章节思维导图

几个真正花心思的产品设计

这个产品看起来是「OCR + 整理」，但难点都在细节规则里。我举三个例子：

1. 划线句不是连贯句子怎么办

用户划线的句子经常是半句、或者跳过中间内容，直接提取会得到语义断裂的碎片。我的处理规则是：在不改变原意的前提下，参考前后划线句或划线句周边的内容，把碎片整理成逻辑通顺的句子，并去掉「我 / 你」这类个人指向性表述。整理时按「结论先行、以上统下、归类分组、逻辑递进」的金字塔原则，只保留一层结构，避免把笔记变成小作文。

2. 怎么知道这句话在书里的位置

我用三重信息做章节定位：书籍目录（章节标题）、拍照页边角的当前章信息、以及页码。三者结合，才能把一句划线句放回正确的章节与顺序里，而不是简单按拍照顺序堆叠。

3. 怎么让笔记进入用户已有的工具

产品不试图成为用户的「唯一笔记软件」。MVP 支持导出 PDF / 文本 / Markdown，并规划了导入到印象笔记、飞书、Notion 等产品的路径——降低用户的迁移成本，才有机会被真正用起来。

实现：一个人把前后端都写完

为了验证效率，我选择自己实现全部链路：前端用 uni-app + Vue 3 + TypeScript，一套代码覆盖微信小程序与 H5；后端用 Go + Gin + GORM + MySQL，负责书籍、笔记、OCR 与 AI 整理；对象存储用云 COS，登录走微信授权与 JWT；OCR 接入微信 OCR 能力，文本合并与思维导图交给大模型处理。

工程上刻意做了几件事：用 MVVM + Pinia 管理状态、用 TDD 倒逼接口实现、把「简单需求 → PRD → 一页架构 → MVP 看板 → 分任务实现 → 真机验证」固化成流程。这段经历让我确认：一个人也能把产品做到上线，但「能上线」和「值得继续做」是两件完全不同的事。

结局：上线内测后，我选择了止损

MVP 上线并完成小范围验证后，我复盘时发现价值假设正在失效：

  • Notion 已经能做 OCR 识别、智能整理与 AI 辅助，且整理效果更好；
  • Manus 这类 Agent 产品可以把「识别 → 整理 → 导图」串起来；
  • 笔记类产品要加 OCR 与思维导图并不难，AI 教练只需接入 LLM——我的差异化会被平台能力快速抹平。

这意味着：即使我把体验做得更好，用户也没有理由从已有工具迁移过来。继续投入只会变成「坚持」，而不是「验证」。所以我停掉了这个项目，把精力转向我认为差异更明确、且与自身经历更匹配的方向——AI 搜索时代的品牌可见性（GEO）。

复盘

这次止损让我形成了两个判断标准：第一，先确认「谁会为它改变现有习惯」，再决定要不要做；第二，平台能力会持续吞掉工具型产品的差异化，产品要么有数据/工作流壁垒，要么有垂直 know-how，否则很难长期成立。

这段经历留下的东西

  • 完整走通了一个产品从调研、PRD、架构、实现、上线到复盘的全过程；
  • 具备了「把模糊需求翻译成技术方案」的能力，也能独立评估成本与风险；
  • 更重要的是：知道什么时候该停。这比多做一个功能更值钱。
