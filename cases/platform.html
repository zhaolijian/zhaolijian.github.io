案例 03 · B 端产品与中台 2022.07 – 2025.03 一线互联网公司 · 在线教育公司

B 端产品与中台：让复杂系统变成业务方能用的产品

在一线互联网公司企业协作产品与在线教育公司三大业务中台，我做的是「研发 + 产品」的复合角色：既写服务端，也承接业务方需求、写 PRD、定优先级、推动多端落地。这段经历训练的是 B 端产品最重要的能力——在复杂约束里把边界说清楚。

我的角色
服务端研发 / 兼产品接口人（需求 → PRD → 验收 → 上线）
服务对象
5+ 业务线；金融、互联网、制造等行业客户场景
代表项目
组织架构权限、薪酬自定义字段、动态配置 / 流控 / 消息队列中台
结果口径
一次上线零回滚、零客诉、4 次大促零事故

背景：B 端产品的难点不是功能，是边界

B 端系统里，一个看似简单的需求往往同时牵动：多个业务线的不同流程、Web 端与 OpenAPI 的一致性、历史数据的兼容、以及上线后不能回滚的风险。产品经理如果只把需求翻译成功能，最后一定会被复杂度反噬。

我在在线教育公司的两年里长期同时负责动态配置、流控、消息队列三大业务中台的 SDK 与 Web 平台两端，日常承接 5+ 业务线需求；在一线互联网公司企业协作产品负责 B 端核心功能的服务端研发，与 PM 协作完成权限与字段方案的多端落地。两段经历让我形成了一个固定的工作方式：先把边界和验收讲清楚，再谈实现。

案例一：组织架构调整的权限方案

企业客户在组织架构调整时，最敏感的是「谁能看到谁的薪酬与人事信息」。原来的权限模型无法表达「部门负责人」和「HRBP」在同一份数据上的不同可见范围，导致客户在调整组织时要么权限过大、要么流程走不通。

  • 角色拆分：与 PM 协作设计「部门负责人 vs HRBP」两类角色的权限差异，并落到字段级隔离，而不是只做菜单级权限；
  • 多端一致：同一套权限规则要同时覆盖 Web 端、多维表格与 OpenAPI，避免不同入口的权限表现不一致；
  • 结果：方案一次上线、零回滚。

案例二：薪酬档案的自定义字段

不同行业对薪酬档案的字段需求差异很大：金融客户要复杂的公式与等级，制造客户要班次与计件，互联网客户要期权与调薪记录。如果每个客户都定制开发，产品会被拖垮。

  • 抽象字段类型：把需求收敛为文本、数字、日期、公式等标准字段类型，并定义校验、默认值、可见性与引用规则；
  • 配置而非开发：在 Web 端提供字段配置能力，同时通过 OpenAPI 开放给客户的系统集成；
  • 兼容旧逻辑：新字段体系必须兼容存量数据与老接口，上线后零客诉。

案例三：三大业务中台的产品化

在线教育公司的三大中台组件由我长期同时负责。它们的共同问题是：能力很强，但业务方不会用、不敢用。我把每个组件都当作一个 B 端产品来做——不只交付 SDK，还交付 Web 管理平台、接入文档与自助排查能力。

组件原来的问题我做的产品化改造结果
动态配置 误删配置导致线上故障；历史版本不可查；积压配置不敢清理 基于 MySQL binlog 订阅自建历史配置表；Web 端提供永久保存、历史回溯、自助查询与「配置—服务」关系可视化 5+ 业务线清理无效配置 1000+ 条，基本杜绝误删配置引发的线上故障
流控 规则变更要改代码并重新部署，平均 45 分钟 SDK 侧做 HTTP/RPC 流量自动识别与拦截的自动埋点（业务方零代码接入）；Web 端可视化配置与动态下发 配置生效从 45 分钟降到 2 分钟，保障 4 次大促零事故
消息队列 发布风险高；测试环境串通；不支持超长延迟消息；资源关系不可视 SDK 侧智能路由（细粒度注册 + 环境标识隔离）；Web 端资源全生命周期可视化；支持蓝绿灰度、虚环境隔离与 40 天以上超长延迟 测试环境零串通，故障定位时长约缩短 50%
产品方法

每个需求都按同一套闭环走：业务方提需 → 记录需求文档 → 评审会定优先级与排期 → 撰写 PRD → 开发与测试 → 业务方验收 → 验收通过后上线。技术背景让我能提前判断实现成本与风险，但真正让需求落地的，是把「业务方的原话」翻译成「可验收的产品行为」。

这段经历给我的产品判断

先定边界，再定功能

B 端需求没有「全都要」的解法。把不做什么、影响哪些端、怎么回滚写在 PRD 前几行，能省掉后面一半的返工。

产品价值 = 业务方能自助

中台组件是否成功，不看 SDK 能力多强，而看业务方能不能自己配置、自己排查、自己上线。

兼容性就是产品体验

B 端用户对「改坏了」的容忍度极低。存量兼容、灰度发布、可回滚，是产品设计的一部分。

技术背景是双刃剑

懂技术能让我快速判断可行性，但也容易过早陷入实现细节。我现在会刻意先问「用户的问题是什么」，再问「怎么实现」。

结果与边界

这段经历的直接结果是可量化的：5+ 业务线接入、清理 1000+ 无效配置、流控配置从 45 分钟降到 2 分钟、故障定位缩短约 50%、4 次大促零事故、权限方案一次上线零回滚、薪酬字段方案零客诉。

边界也需要说明：这些是公司内部系统与客户交付场景，我无法公开内部文档、客户名称与系统实现细节，因此这个案例只呈现我负责的部分与方法，不包含内部数据与客户信息。
